# Private Spaces rollout

1. Deploy the backend and frontend together. Existing Spaces URLs are mapped to the authenticated `/api/files/object?key=...` endpoint; new uploads return that URL and use private ACLs. Verify image and document rendering while existing objects are still public. Custom `S3_FOLDER` values must also be set as `NEXT_PUBLIC_S3_FOLDER` at frontend build time (the deployment scripts set it).
2. On the deployment host, back up the database and audit the bucket policy, CDN endpoint, and any externally shared direct links. Disable public bucket policies and CDN delivery for the app prefix; object ACLs alone cannot override bucket-wide public access. Do not migrate until frontend mapping is live. Ensure the Space key can list the bucket and read/write object ACLs.
3. From the repository root on the host, with the production env file (mode 600), run `node --env-file=backend/.env scripts/private-spaces-acl.cjs` to inspect all objects under `S3_FOLDER/`. The script defaults to dry-run and never prints credentials. Review the exact prefix and the listed objects.
4. Run `node --env-file=backend/.env scripts/private-spaces-acl.cjs --apply BUCKET/FOLDER/`, substituting the actual configured bucket and folder. The confirmation must match the env exactly. Re-run dry-run and verify there are zero public ACLs. The migration is restartable and skips objects whose ACL is already private. A failed ACL operation exits nonzero; re-run after resolving it. Existing clients using bearer tokens instead of cookies must also switch to a cookie jar for login and refresh; tokens are no longer returned in JSON.
5. Verify unauthenticated direct Spaces requests fail, authenticated proxy requests render, anonymous proxy requests fail, and purge/disable CDN caches. Old public URLs in database remain unchanged; the frontend maps them at render time. Any old externally shared URLs will stop working. If public distribution is genuinely needed, expose an **authorized** signing endpoint after a per-object access check and use `FilesService.getSignedUrl(key, expiresIn)` with a short expiry; do not restore `public-read` or sign arbitrary caller-supplied keys.

Never paste credentials into commands or commit `.env`. The script only changes object ACLs within the configured prefix; it does not alter bucket policies, CDN settings or database records. Objects with an unsupported legacy extension or MIME cannot be served by the proxy and must be reviewed/remediated separately.
